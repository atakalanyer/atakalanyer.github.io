Project Overview

What it is

A university-focused social networking and project collaboration platform for students and academics of Fatih Sultan Mehmet Vakıf University. Students can share projects, find teammates, follow each other, join clubs and register for events.

The problem

Project ideas, teammates, clubs and events are usually scattered across chat groups and notice boards. The platform puts them in one place.

Why it matters

A shared network makes it easier for students to find collaborators with the right skills and to take part in campus activities.

Objectives

  • Let users register with e-mail verification and role-based access.
  • Support project posts, team matching and applications to join a team.
  • Support clubs, events, registration, check-in and certificates.
  • Provide profiles, follows, messages and notifications.
  • Give administrators tools to manage content and feedback.

  • AdministrationAn admin page for content moderation, reports and site feedback.

Architecture and data

The repository contains a React front end and an Express.js API backed by SQL Server. The front end also uses Supabase and Netlify Functions.

Front endReact 18 with React Router, built with Vite. 43 components and 18 page files, including the feed, explore, project detail, profile, clubs, events, messages and admin screens.
REST API (backend/)Express.js 5 with route modules for auth, lookup, users, clubs, projects, posts, events and notifications. JWT for sessions, bcryptjs for password hashing, Nodemailer for e-mail, and the mssql package to talk to SQL Server.
Serverless layerNetlify Functions handle one-time codes, sign-in, registration, password reset, push notifications and an assistant endpoint.
Supabase clientThe front end reads and writes tables such as projects, profiles, clubs, events, announcements, reports, notifications and follows through Supabase (for example projects, profiles, announcements, reports, event check-ins and notifications).

Key Takeaways

A broad feature surface

The project combines authentication, social features, team matching, clubs and events in one application.

Two data paths

The repository holds a SQL Server API and a Supabase-backed front end, a useful comparison of two ways to build the same kind of system.

Challenges & Solutions

Technical challenges

  • Role-dependent access to pages and API routes.
  • One-time-code verification and e-mail delivery.
  • Keeping many related entities (users, projects, clubs, events) consistent.

Important decisions

  • Used role guards on both the front end and the API.
  • Hashed passwords with bcryptjs and issued JWTs for sessions.
