Project Overview

What it is

A regression project on real estate listings from five neighborhoods of Eyüpsultan, Istanbul: Alibeyköy, Çırçır, Karadolap, Yeşilpınar and Akşemsettin. I collected the data myself, cleaned it, and compared four regression models.

The problem

Estimate the listing price of an apartment from its size, age, rooms, neighborhood and keywords in the listing title.

Why it matters

Local prices depend on factors that national datasets do not cover. Building the dataset from scratch shows the full path from raw web data to a tuned model.

Objectives

  • Predict prices from real listing data.
  • Apply data cleaning and feature engineering techniques.
  • Compare different regression models.
  • Use hyperparameter optimization and cross-validation.
  • Visualize predictions, errors and feature importance.

Dataset Information

Source
Sahibinden.com listings collected with Instant Data Scraper
Rows
1,038 raw listings; 956 after cleaning and outlier removal
Columns
6 raw columns (title, gross m², rooms, price, neighborhood, building age)
Target
fiyat_tl (listing price in Turkish lira)

Important features

  • Gross area (m²)
  • Building age
  • Room and living-room counts
  • Neighborhood (one-hot encoded)
  • Keywords extracted from listing titles

Data characteristics

  • The cleaned set holds 956 listings: Çırçır 261, Yeşilpınar 226, Karadolap 165, Akşemsettin 165, Alibeyköy 139.
  • Prices are asking prices, not final sale prices.
  • The final observation count depends on the cleaning steps.

Methodology

  1. Data Collection

    Scraped listings that matched the search criteria from Sahibinden.com with Instant Data Scraper.

  2. Data Cleaning

    Shuffled the rows, normalized text, removed duplicates, converted the price column to integers and filtered impossible records using price per square meter.

  3. Outlier Handling

    Detected outliers in price and area with the IQR method and saved a cleaned CSV.

  4. Exploratory Data Analysis

    Price distribution, price by neighborhood and gross area against price.

  5. Feature Engineering

    Split room strings into room and living-room counts, created keyword features from titles and one-hot encoded neighborhoods.

  6. Model Development

    Ridge Regression, Decision Tree, Random Forest and Gradient Boosting regressors.

  7. Hyperparameter Optimization

    RandomizedSearchCV with 5-fold KFold cross-validation.

  8. Model Evaluation

    Compared cross-validated R², test R² and test MAE.

  9. Model Explainability

    Permutation importance, partial dependence plots, residual analysis and a shallow decision tree visualization.

Key Findings & Insights

Tree ensembles beat the linear model

Random Forest and Gradient Boosting both scored higher test R² than Ridge Regression (0.648 and 0.611 versus 0.513).

Random Forest led on every reported metric

It had the highest CV R² and test R² and the lowest test MAE, about 1.05 million TL.

Area explains part of the price

In the cleaned data, gross area and price are moderately correlated (about 0.55), so area alone is not enough.

Neighborhood medians are close

Median listing prices range from about 6.95 million TL (Yeşilpınar) to 7.65 million TL (Akşemsettin). Both figures were computed from the cleaned CSV.

Challenges & Improvements

Technical challenges

  • Scraped listings contain duplicates, inconsistent text, typos and impossible values.
  • Room information and listing titles had to be turned into numeric features.

Important decisions

  • Filtered inconsistent records using price per square meter before applying the IQR rule.
  • Used cross-validation and a separate test set to compare models fairly.

Limitations

  • Data covers five neighborhoods and one collection period.
  • Listing prices can differ from real transaction prices.
  • Some factors that affect price are not in the dataset.
  • With R² of 0.648, a typical error of about 1 million TL remains.

Potential improvements

  • Collect more listings and more features.
  • Compare other outlier handling methods.
  • Run a more extensive hyperparameter search.
  • Add SHAP for global and local explainability.
  • Turn the model into a small Flask or Streamlit prediction app.
