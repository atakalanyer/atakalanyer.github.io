Project Overview

What it is

A stationery store website developed as a web development project. It has a home page, product and category pages, an about page and a contact page, all styled with one shared stylesheet.

The problem

A small shop needs a clear online presence: what it sells, what things cost, whether they are in stock, and how to reach it.

Why it matters

It practices the basics of server-side web development: PHP data structures, loops, conditionals and form handling.

Objectives

  • Present products by category with prices and stock status.
  • Generate repeated page elements with PHP instead of copying markup.
  • Provide a contact page with a validated form.
  • Keep the look consistent with a shared stylesheet.

Main Features

  • Home pageHero section, four category cards, a short list of advantages and a best-sellers table built from PHP arrays.
  • Categories and productsPages for pens, notebooks, paper and drawing tools, and detail pages for individual products.
  • Stock indicatorA PHP condition shows 'in stock' or 'limited stock' in different colors.
  • Price calculationProduct pages show unit price, quantity and the total amount.
  • Contact pageA form with server-side validation, an opening-hours table, an embedded map and a WhatsApp live-support button.
  • About pageMission statement and the shop logo.

Implementation Details

  • Data in PHP arraysCategories, advantages, best sellers and opening hours are arrays rendered with foreach loops.
  • Conditional outputif / else blocks decide the stock message and the status colors.
  • Form handlingThe contact page checks the request method, validates that both fields are filled in and shows an error or a confirmation.
  • One stylesheetstyle.css styles every page, including the navigation bar, cards, tables and the floating WhatsApp button.

Key Takeaways

Server-side templating in practice

Most repeated markup is generated from arrays, which keeps the page files short and easy to change.

Complete page flow

Every page links to the others through a shared navigation bar, from the home page to a single product.

Challenges & Solutions

Technical challenges

  • Keeping many product pages consistent without a database.
  • Handling form input safely on the server.

Important decisions

  • Used PHP arrays instead of a database to keep the project small.

Limitations

  • Products and prices are hard-coded, so changing them means editing code.
  • The contact form shows a confirmation but does not send the message anywhere.
  • The 'add to cart' button is only a demo alert.

Potential improvements

  • Move products to a MySQL database and load them dynamically.
  • Escape all output with htmlspecialchars and send form messages by e-mail.
  • Add a real shopping cart.
  • Make the layout responsive for phones.
