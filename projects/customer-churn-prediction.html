Project Overview

What it is

A classification project on the IBM Telco Customer Churn dataset. It identifies customers who are likely to leave a telecom provider and uses SHAP to show which factors drive each prediction.

The problem

A telecom company loses revenue when customers cancel. The model estimates churn risk per customer so that retention effort can be aimed at the people most likely to leave.

Why it matters

Knowing who is at risk, and why, turns a vague retention goal into concrete actions such as targeted offers or better onboarding.

Objectives

  • Analyze customer behavior and churn patterns.
  • Clean the data and perform exploratory analysis.
  • Engineer features that describe customer behavior.
  • Build and compare classification models.
  • Optimize hyperparameters and the classification threshold.
  • Explain predictions with SHAP and derive business insights.

Dataset Information

Source
IBM Telco Customer Churn dataset
Rows
7,043 customer records
Columns
21 original columns
Target
Churn (Yes / No), binary classification

Important features

  • Demographics
  • Account information
  • Subscribed services
  • Contract type
  • Payment method
  • Billing details (tenure, MonthlyCharges, TotalCharges)

Data characteristics

  • Imbalanced: fewer churn cases than non-churn cases.
  • TotalCharges is stored as text and has missing values for customers with zero tenure.
  • The held-out test set contains 1,409 customers, 374 of whom churned.

Methodology

  1. Data Cleaning

    Checked missing values and duplicates, converted TotalCharges to numeric, handled the missing values that belong to customers with zero tenure, and dropped customerID because it is an identifier, not a feature.

  2. Exploratory Data Analysis

    Compared churn rates across tenure, contract type, services and payment method. Short tenure and month-to-month contracts stood out as higher-risk groups.

  3. Feature Engineering

    Created ServiceCount, TenureGroup, HasTechSupport, HasOnlineSecurity and AverageMonthlySpend. AverageMonthlySpend was left out of training because it was highly correlated with MonthlyCharges.

  4. Data Preprocessing

    Stratified train-test split, StandardScaler for numeric features, OneHotEncoder for categorical features and SimpleImputer, combined in a ColumnTransformer and Pipeline.

  5. Model Development

    Compared Logistic Regression and Random Forest. Logistic Regression performed better with the configurations tested.

  6. Hyperparameter Optimization

    GridSearchCV with stratified 5-fold cross-validation selected C = 0.01, class_weight = balanced, penalty = l2 and solver = saga (best CV F1 = 0.6294). The decision threshold was then tuned on out-of-fold predictions and set to 0.56 instead of the default 0.50.

  7. Model Evaluation

    The final Logistic Regression model was evaluated once on the held-out test set.

  8. Model Explainability

    SHAP summary and waterfall plots explain the model globally and for individual customers.

Key Findings & Insights

Tenure matters most

Newer customers form the highest churn-risk group.

Contract type is a strong signal

Month-to-month contracts are strongly associated with churn, while longer contracts go with loyalty.

Price sensitivity

Higher monthly charges are associated with higher churn risk.

Support and security services

Customers without technical support show higher churn tendencies; those with online security show lower churn.

Payment method

Electronic check users show higher churn tendencies in this dataset.

Business reading

The data suggests long-term contract incentives, stronger first-year onboarding and promotion of support and security packages. These are observed associations, not proven causes.

Challenges & Improvements

Technical challenges

  • The classes are imbalanced, so accuracy alone hides how many churners are missed.
  • Highly correlated features can blur coefficients and SHAP attributions.

Important decisions

  • Used class_weight = balanced and moved the threshold to 0.56 to balance precision and recall for the churn class.
  • Excluded AverageMonthlySpend to avoid redundancy with MonthlyCharges.
  • Kept Logistic Regression as the final model because it scored better than Random Forest on every reported metric.

Limitations

  • The model has false positives and false negatives (234 and 102 on the test set).
  • Results come from one held-out test split.
  • Real customer populations may behave differently from this dataset.

Potential improvements

  • Evaluate with repeated or nested cross-validation instead of a single split.
  • Try gradient boosting models and probability calibration.
  • Test cost-sensitive thresholds that reflect the real cost of a missed churner.
